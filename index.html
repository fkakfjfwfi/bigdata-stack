建议的学习顺序

这一章的内容有强依赖关系，跳着看会卡。

先建立地图（1.1 → 1.4）

先搞清楚 Hadoop 由哪两个集群组成、每个角色的职责、1.x 为什么不行、2.x 怎么改的。这四节不涉及操作，但决定了后面每一步"为什么要这么做"。跳过这四节，后面全是死记硬背。

再动手搭（1.5 → 1.6）

环境准备、四个 XML、格式化、启动。这两节必须按顺序做，中间任何一步跳过都会在后面报错。1.6 的排错表建议先读一遍再动手——它列的错误你多半会遇到。

最后跑通链路（1.7 → 1.8）

上传下载文件、看块怎么切、跑一个 MapReduce 作业、开历史服务器、理解回收站。这一段的目的是建立"数据在集群里怎么流动"的直觉，为后面 Hive 的 SQL 执行打下基础。

这套笔记怎么来的

和一般课程笔记的区别，在三个地方：

口述补成命令

老师讲课是"这里我们改一下""然后启动它"，提炼时补成了完整可复制的命令和配置文件片段。你看不到他手上的操作，但能直接照着敲。

坑写成对照表

"这里可能会报错"这种话，展开成「现象 → 原因 → 解法」三段式。1.6 那张排错表是整章最该先读的部分。

每句都能回查

每个知识点后面都有 （14 · 05:20–09:10） 这样的标注，指回原视频的集数与位置。有疑问可以直接定位，不用重看四小时。

说清哪里是补充

有些内容课程没讲但工程上必需（比如 -skipTrash、机架感知的具体策略），文中会标"补充"二字，和原课内容区分开。
