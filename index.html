建议的学习顺序

九章之间有强依赖，跳着看会卡。但也分两类：必须按顺序读的（1~5 章），和可以按需跳读的（6~9 章）。

第一段 · 打地基（01 → 02）

先搞清楚 Hadoop 由哪两个集群组成、每个角色干什么、三台机器怎么分。然后深入 HDFS——块、副本、心跳、写数据七步链。这一段不涉及 SQL，但决定了后面所有"为什么这么慢"的答案。

第二段 · 进 Hive（03 → 05）

03 先讲数仓这个领域在做什么（分层、ETL），然后把 Hive 装上。04 是全站最长的一章（建表的三个设计决定：SerDe、内外表、分区分桶），值得慢读。05 讲查询，重点不是语法，是三处「写错不报错只是结果不对」的地方。

第三段 · 拆底层（07 → 08）

07 拆开 SQL 下面那个盒子（天龙八步、Shuffle、YARN），08 讲 ZooKeeper 和 Hadoop HA。这两章是面试的主战场，也是理解 09 章优化的前提——不知道 shuffle 贵在哪，就不知道为什么要把小表放前面。

按需跳读 · 06 与 09

06（高级查询）是工具箱——explode、行列转换、窗口函数，用得到再查。09（优化）建议放到最后：它把前面所有章节的知识都用上了，没学过 04 的分区、07 的 shuffle，读 09 只能背结论。

一条更实际的建议：先做一遍，再回头读原理。

这套课的顺序是"先搭集群再讲架构"，容易让人卡在配置上失去耐心。如果只是想先跑通，就读 01 的 1.5~1.6 + 03 的 3.6~3.7，把 Hadoop 和 Hive 都启动起来，跑一条 select count(*)。有了这个体感，再回头从 1.1 开始读，每个概念都能对上刚才看到的现象。

这套笔记怎么来的

和一般课程笔记的区别，在三个地方：

口述补成命令

老师讲课是"这里我们改一下""然后启动它"，提炼时补成了完整可复制的命令和配置文件片段。你看不到他手上的操作，但能直接照着敲。

坑写成对照表

"这里可能会报错"这种话，展开成「现象 → 原因 → 解法」三段式。1.6 那张排错表是整章最该先读的部分。

每句都能回查

每个知识点后面都有 （14 · 05:20–09:10） 这样的标注，指回原视频的集数与位置。有疑问可以直接定位，不用重看四小时。

说清哪里是补充

有些内容课程没讲但工程上必需（比如 -skipTrash、机架感知的具体策略），文中会标"补充"二字，和原课内容区分开。
